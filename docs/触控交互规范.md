# 移动端触控交互规范 · 小图标触摸热区优化

> 适用：拼豆工坊 Android 端（Jetpack Compose）  
> 版本：v1，随 v2.6.0 落地  
> 屏幕基准：1080 × 2400 px / 411 × 914 dp / density 2.625

---

## 1. 设计目标

小图标（16dp 级别的工具图标、列表里的「⋯」、顶部操作）视觉上必须克制，但手指要够得着。规范核心是**视觉尺寸与交互尺寸解耦**：看得见的保持小，摸得到的至少 28dp、推荐 40dp。

---

## 2. 尺寸规则

| 项 | 规则值 | 本应用落地值 | 说明 |
|---|---|---|---|
| 视觉图标 | 16dp（基准） | 顶部操作 20dp、卡片「⋯」18dp、工具栏图标 = 控件 48% | 视觉可更小，不影响热区 |
| 热区下限 | **28dp** | 硬下限，低于即不合规 | ≈ 7.4mm，指腹最小稳定覆盖 |
| 热区推荐 | **40dp** | 顶部三键、卡片「⋯」、icon-only 工具按钮、底部导航均为 40dp | 主力标准 |
| 扩容方式 | 透明扩容 | Modifier.tapTarget(40.dp) / heightIn(min = Ds.hitTarget) | 不改视觉，只放大命中区 |
| 相邻热区间隙 | **≥ 4dp** | 顶部三键 spacedBy(4.dp)；底部导航每项左右各内缩 2dp（合 4dp） | 禁止热区融合 |
| 滚动边缘缓冲 | **20dp** | 卡片左滑要求起手点距左右边缘 > 20dp；列表底部 contentPadding 32dp | 规避手势冲突 |

### 2.1 取值依据

- **28dp**：指腹能稳定覆盖的最小方形区域；再小用户必须瞄准。
- **40dp**：拇指自然落点，介于 Material 48dp 与 iOS 44pt 之间，适配 411dp 宽度下「一行放 3 个操作」的密度上限。
- **4dp 间隙**：低于 4dp 时相邻热区在命中算法上会被合并，夹缝点击会命中上一个按钮，产生点错体感。

---

## 3. 交互规则

### R1 视觉与热区解耦
图标按视觉尺寸绘制，热区用透明扩容补足。禁止用放大图标来凑热区。

### R2 热区禁止融合
相邻可点元素必须留 ≥ 4dp 空隙；等宽分栏（如底部导航）用**内缩**而不是撑满来制造间隙。

### R3 滑动容器边缘留缓冲
横向手势（左滑出菜单）与纵向滚动共存时，手势入口必须离容器边缘 ≥ 20dp，避免与系统返回手势、列表滚动抢事件。

### R4 点击必须有过手反馈
所有命中都要有 Taptic 级触觉反馈（HapticFeedbackType.TextHandleMove），弥补拇指遮挡视线导致的「不确定点没点上」；视觉侧配合 pressScale 缩放回弹。

### R5 单一命中原则
一次点击只触发一个动作：热区不重叠、不嵌套；父容器可点（整张卡片）时，子按钮（「⋯」）必须自己消费事件。

## 4. 坑点说明

| 坑 | 现象 | 根因 | 对策 |
|---|---|---|---|
| 热区等于图标 | 点了没反应，要瞄准两次 | 直接给 Icon(size=16.dp) 挂 clickable | 外层容器 heightIn(min=40.dp)，图标居中 |
| 热区重叠 / 融合 | 点 A 触发 B，夹缝点击行为随机 | 相邻元素 padding 为 0 或等宽撑满 | 相邻留 4dp 内缩，边界显式计算 |
| 紧贴滚动区 | 想滚动却打开了卡片 / 菜单 | 可点区域与滚动容器无缓冲 | 边缘 20dp 只给滚动手势 |
| 图标中心偏移 | 视觉居中但热区偏一侧 | 用 padding 凑尺寸而非尺寸容器 | 统一 Box(contentAlignment=Center) + 固定尺寸 |
| 触觉滥用 | 手指滑动时不停震动 | haptic 挂在 pointerInput 的移动回调里 | 只在 onClick 命中时触发一次 |
| 只有震动没有视觉 | 用户以为没点上 | 缺少按下态 | pressScale + 选中态染色 |

## 5. 验收标准

1. **可达性**：任意可点图标的实际命中矩形 ≥ 28 × 28dp；主力操作 ≥ 40 × 40dp。
2. **间隙**：相邻热区最小距离 ≥ 4dp（Layout Inspector 量 bounds，不允许相交）。
3. **缓冲**：横向手势起点距容器左右边缘 ≥ 20dp 才响应；边缘起手只滚动。
4. **反馈**：每次命中产生一次触觉反馈，连续快速点击不叠加。
5. **单命中**：任一坐标最多落入一个热区；卡片内「⋯」不触发打开卡片。
6. **可测**：以上尺寸全部以 dp 常量表达（Ds.hitMin / Ds.hitTarget / Ds.hitGap / Ds.scrollBuffer），不允许散落魔法数。

## 6. 错误案例

### 6.1 热区和图标一样大

    反例：Icon(painter, null, Modifier.size(16.dp).clickable { onTap() })
    结果：命中率极低，用户反复点空。

    正解：
    Box(
        Modifier.size(Ds.hitTarget).clickable { onTap() },   // 热区 40dp
        contentAlignment = Alignment.Center,
    ) { Icon(painter, null, Modifier.size(16.dp)) }          // 视觉仍 16dp

### 6.2 热区重叠

    反例：Row { repeat(3) { i -> Box(Modifier.weight(1f).clickable { pick(i) }) { Icon() } } }
    结果：等宽 + 零间隙，三项热区连成一片，落在分割线附近命中邻项。
    正解：每项左右各内缩 2dp，形成 4dp 间隙（本应用已按此实现）。

### 6.3 紧贴滚动区

    反例：Modifier.pointerInput(Unit) { detectHorizontalDragGestures { _, drag -> ... } }
    结果：从屏幕边缘起手时与系统返回手势 / 列表滚动抢事件，滑动卡住或误开菜单。
    正解：onDragStart 校验 offset.x in 20dp..(width - 20dp)，边缘只给滚动（本应用已按此实现）。
